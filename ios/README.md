# Голос — нативный iOS-клиент

Этот каталог — нативное приложение для iPhone. Существующая PWA в `voice-note/` и основной MindForge не изменяются.

## Что уже входит

- SwiftUI-интерфейс iPhone.
- Ручная запись встреч и заметок с микрофона.
- Импорт аудиофайлов из Files.
- CallKit observer как диагностический эксперимент по видимости системных вызовов.
- Встроенный номеронабиратель для собственного VoIP-сервиса.
- Twilio Voice SDK 6.13.8 через Swift Package Manager.
- Интеграция исходящих звонков через CallKit и Twilio Voice.
- PushKit/CallKit каркас для входящих звонков.
- Настройки HTTPS backend и токена приложения; токен сохраняется в Keychain.

## Ограничение iOS — не перехватываем чужие звонки

Приложение не может получить аудио обычного сотового звонка, который обслуживает Phone, или звонка WhatsApp, Telegram, FaceTime и других сторонних приложений. CallKit не предоставляет аудиопоток чужого звонка. Никакой jailbreak, подмена аудиосессии или скрытая запись не используется.

Телефонный экран «Голоса» работает только для звонков, которые пользователь совершает или принимает через отдельную инфраструктуру VoIP. Звонок на обычный телефонный номер проходит через Twilio и PSTN; это не SIM-вызов iPhone.

## Сервер

Сервер расположен в `../voice-backend/`. Он выдаёт короткоживущие Voice Access Tokens, маршрутизирует вызовы, проверяет подписи webhook-запросов Twilio и сохраняет события двухканальных записей. Сами записи остаются в аккаунте Twilio до защищённой загрузки с backend.

Инструкции по развертыванию и настройке Twilio: [voice-backend/README.md](../voice-backend/README.md).

## Что необходимо настроить перед реальными звонками

1. Развернуть `voice-backend` на публичном HTTPS-хосте с постоянным диском для каталога данных.
2. В переменные окружения backend внести Twilio Account SID, Auth Token, API Key SID/Secret, TwiML Application SID и номер Caller ID. Секреты не помещать в GitHub и не отправлять в чат.
3. Создать TwiML Application с Voice URL `/v1/voice/twiml`.
4. Настроить входящий webhook номера на `/v1/voice/incoming`.
5. Установить `GOLOS_APP_API_TOKEN` и тот же токен в защищённом поле приложения.
6. Явно задать `ALLOWED_DIAL_PREFIXES`. Пустое значение блокирует исходящие звонки.
7. Для входящих вызовов настроить VoIP Push Credential в Twilio и Apple Developer/APNs, после чего установить SID в `TWILIO_PUSH_CREDENTIAL_SID`.
8. Подписать приложение собственной Apple Developer Team и проверить вызовы на физическом iPhone.

На этом этапе код мобильного приложения и backend добавлен, но реальный вызов не тестировался: для него нужны действительные credentials, телефонный номер, публичный сервер, APNs-настройка и устройство с подписью.

## Запись и согласие

Для звонков через Twilio backend включает двухканальную запись с момента ответа и проигрывает голосовое уведомление обеим сторонам. Голосовое уведомление само по себе не гарантирует юридически достаточное согласие. Перед использованием необходимо проверить местные правила и получить требуемое согласие всех участников; при возражении участника запись/разговор нужно прекратить.

## Сборка

GitHub Actions собирает iOS Simulator arm64, поскольку бинарный XCFramework Twilio SDK не содержит x86_64 simulator slice. Для физического iPhone понадобится настройка подписи и provisioning profile.
