# Голос — нативный iOS-клиент

Ветка содержит нативное приложение iPhone и отдельный телефонный backend. PWA в `voice-note/` и основная ветка `main` не меняются.

## Реализовано в коде

- SwiftUI-клиент iPhone.
- Запись встреч и заметок через микрофон, импорт аудиофайлов. После завершения записи запускается серверная AI-обработка.
- Диагностическое наблюдение за состоянием системных вызовов через CallKit — без доступа к аудио этих вызовов.
- Twilio Voice SDK 6.13.8: исходящие PSTN-звонки из приложения через собственный телефонный шлюз.
- PushKit и CallKit для входящих VoIP-вызовов на подключённый Twilio-номер.
- Персональный HTTPS backend URL и ключ приложения; ключ хранится в iOS Keychain, секреты Twilio остаются на сервере.
- Проверка соединения с backend через выдачу короткоживущего Voice Access Token.
- Отдельное разрешение владельца приложения на запись; подтверждение вызываемого абонента для исходящего звонка и звонящего для входящего — клавишей 1 до соединения.
- Серверная двухканальная запись завершённых звонков через Twilio.
- Экран записей звонков, защищённое скачивание MP3 и автоматическое обновление списка после завершения вызова.
- AI-конвейер для аудио: diarized-транскрипция с временными метками и спикерами, резюме, ключевые тезисы, решения, задачи и открытые вопросы.
- Отдельная библиотека AI-записей, полнотекстовый серверный поиск, повторное открытие расшифровки и удаление записи/аудио.
- Перед записью встречи приложение требует подтвердить, что участники уведомлены и получено требуемое согласие.
- Node.js backend в `voice-backend/`: подписанные Twilio webhooks, allowlist исходящих E.164-направлений, события согласия и защищённая выдача MP3.

## Ограничения — что приложение не перехватывает

Приложение не получает аудио сотового вызова из Apple's Phone и не перехватывает WhatsApp, Telegram, FaceTime, Zoom или другие сторонние приложения. Оно записывает только звонки, которые проходят через собственный VoIP/PSTN-шлюз «Голоса».

Это означает:
- исходящий звонок совершается из номеронабирателя приложения через телефонный сервис, а не через SIM-звонилку iPhone;
- входящий вызов должен поступить на подключённый Twilio-номер; существующий SIM-номер сам по себе не перехватывается;
- при необходимости можно отдельно настроить переадресацию оператора на телефонный номер «Голоса», если оператор и тариф это позволяют.

## Что требуется для фактической работы AI и звонков

1. Создать Render backend из `render.yaml` в корне репозитория. Blueprint использует платный план Starter и постоянный диск 5 ГБ; публикацию нужно вручную подтвердить в Render.
2. Добавить `OPENAI_API_KEY` и конфигурацию Twilio в секреты/переменные Render. В Blueprint `GOLOS_APP_API_TOKEN` генерируется автоматически. Хранить ключи только на сервере, не в приложении, GitHub или чате.
3. Настроить исходящие/входящие Twilio webhooks и разрешённые E.164-префиксы.

## Что требуется для реальных звонков

1. Развернуть `voice-backend` на публичном HTTPS-хосте с постоянным диском для `DATA_DIR`.
2. Создать и настроить Twilio Programmable Voice, API key, TwiML Application и голосовой номер.
3. Заполнить переменные окружения backend: Account SID, Auth Token, API Key SID/Secret, TwiML App SID, Caller ID и разрешённые E.164-префиксы. Секреты не помещать в GitHub или чат.
4. Создать Twilio Push Credential и настроить Apple APNs для доставки входящих VoIP-вызовов в фоне.
5. Установить персональный `GOLOS_APP_API_TOKEN` в backend и в настройках приложения.
6. Подписать приложение через Apple Developer Team и проверить входящие и исходящие вызовы на физическом iPhone.

Без публичного сервера, действительных credentials, телефонного номера, APNs-настройки и подписанного приложения реальные звонки ещё не заработают. Успешная CI-сборка подтверждает компиляцию для iOS Simulator, но не заменяет реальный телефонный тест.

## Запись и согласие

Для исходящего звонка владелец приложения заранее включает разрешение записи, а вызываемый абонент подтверждает её клавишей 1 в голосовом меню. Для входящего PSTN-звонка сначала клавишей 1 соглашается звонящий; затем вызов направляется в приложение. При отключённом разрешении владельца приложения входящий записываемый вызов отклоняется. События подтверждения сохраняются в `recording-consents.jsonl`.

Это техническая фиксация выбора, а не юридическое заключение. Перед использованием необходимо проверить применимые правила и дополнительные требования к согласию во всех странах участников.

## Проверки и статус

- GitHub Actions успешно собирает нативный iOS target для Simulator.
- Backend tests и проверка JavaScript-синтаксиса проходят в GitHub Actions.
- Физический iPhone, входящие/исходящие реальные звонки и доставка APNs push пока не проверялись.
- AI-конвейер подключён в коде, но не заработает до развёртывания backend и добавления OPENAI_API_KEY. Одно загружаемое аудио ограничено 23 МиБ; длинные записи пока необходимо делить вручную.

## Версия и подпись приложения

- Текущая версия: `0.3.0` (build `3`), Bundle ID: `com.blackministers.golos`.
- Подпись больше не отключена на уровне Xcode target. Debug использует APNs `development`, Release — отдельный `GolosRelease.entitlements` с APNs `production`.
- Для подписи в Xcode необходимо выбрать Apple Developer Team и настроить provisioning profile/App ID. TestFlight требует действительного Apple Developer Program аккаунта и App Store Connect приложения/API credentials.
